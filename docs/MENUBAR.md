# 菜单栏折叠（Menu Bar Fold）

解决的问题：**菜单栏图标太多放不下，被系统裁掉，找不到也点不到。**

---

## 一、先说清楚三件事能不能做

这是本功能所有设计取舍的根源，实测得出（见下方"实测证据"）：

| 想要的能力 | 能做到吗 | 代价 |
|---|---|---|
| 把选定的一组图标折叠起来/展开 | ✅ 能 | **零权限** |
| 列出**全部**菜单栏项（含被裁掉、看不到的） | ✅ 能 | 辅助功能 |
| 读出它们的**文字状态**（"已连接"、"未读 3 条"） | ✅ 能 | 辅助功能 |
| **替你点击**它们，弹出那个 App 自己的菜单 | ✅ 能 | 辅助功能 |
| 底部系统实时状态（CPU/内存/磁盘/网络） | ✅ 能 | **零权限** |
| 在面板里显示图标**本来的样子**（图形状态） | ⚠️ 部分 | 屏幕录制，且**只对可见的项有效** |

### 为什么"显示图标本来的样子"需要屏幕录制

`NSStatusItem` 的图标是**拥有它的那个 App 在自己进程里画到自己窗口上的像素**，
系统只负责把那个窗口合成到菜单栏位置。系统**没有把"图标图像"作为数据暴露给任何人**。

实测证据：macOS SDK 的 `AXAttributeConstants.h` 里一共 **203 个** Accessibility 属性常量，
其中跟 image / icon / picture / bitmap / pixel 有关的：**0 个**。

```bash
grep -oE "kAX[A-Za-z]*(Image|Icon|Picture|Bitmap|Pixel)[A-Za-z]*Attribute" \
  .../HIServices.framework/Headers/AXAttributeConstants.h | sort -u
# → 空
```

所以想让面板里的小图跟菜单栏里长得一模一样，唯一办法是复制那一小块屏幕像素。

### 而且：截屏也救不了被裁掉的图标

被系统裁掉的项**根本没有被绘制到屏幕上**，所以截屏同样拿不到它们。
Bartender / Ice 的做法是"临时把它挪进可见区、截一张、再挪回去"，代价是菜单栏可见的抖动。

**LidAwake 不做这件事。** 真实图标预览只对当前可见的项生效，隐藏项一律回退到
「App 应用图标 + 文字状态」。这也说明后者才该是主表示，前者只是锦上添花 —— 所以它默认关闭。

### 为什么不能"免权限地枚举"

试过：靠 `activationPolicy == .accessory` 判断菜单栏 App，实测列出 **59 个**，
其中大部分是 `WebKit.GPU` / `WebKit.Networking` 这类 XPC 服务，
而真正关心的 ToDesk / UniConnect / 飞书 **一个都不在里面**（它们是普通 App，只是顺便挂了状态栏项）。

`CGWindowList` 也不行：在 macOS 26 上扫菜单栏条带的 121 个窗口，
layer 25 只有「控制中心」自己的 15 个，第三方 status item 一个都拿不到（连本 App 自己的也拿不到）。

**结论：可靠枚举只有 Accessibility 这一条路。**

## 二、折叠是怎么实现的（零权限）

菜单栏项从右往左排，塞不下的从**左端**被裁掉。LidAwake 插一个可变宽度的"隔断"项：

```
撑开（折叠中）:  [被顶出屏幕的图标............] ⋮←10000pt→ 〉[控制中心][时钟]
收窄（展开中）:                    [图标][图标][图标] ⋮ 〉[控制中心][时钟]
```

- **⋮ 折叠边界** —— 按住 ⌘ 拖动它，**它左边**的图标属于被折叠的那一组。位置会被记住
- **〉切换按钮** —— 单击折叠/展开，右键打开面板

这就是 Hidden Bar / Dozer 的原理，纯公开 API，不需要任何权限。

**局限要讲清楚**：这个办法只能"选择哪一组不显示"，**不能凭空腾出空间**。
如果你的图标总宽度本来就超过菜单栏，折叠能让你在两组之间切换，但没法让所有图标同时可见。
真正"一次看全"的地方是面板。

## 三、面板

`⌥⌘B` 或右键切换按钮唤起：

```
┌────────────────────────────────────────────┐
│ 菜单栏项目 14 个 · 其中 3 个屏幕上放不下      │
├────────────────────────────────────────────┤
│ [图标] ToDesk        已连接        看不到 › │  ← 橙色"看不到"标记
│ [图标] UniConnect                 看不到 › │
│ [图标] 飞书          未读 3 条            › │
│ [图标] Kaka          防止屏幕休眠中        › │
│ …                                          │
│              [ 折叠菜单栏图标 ]             │
├────────────────────────────────────────────┤
│  CPU·负载2.7   内存·53/128GB  磁盘·可用1.4TB  网络·en0 │
│    9%             42%        ↓0B/s↑1MB/s   ↓56KB/s↑18KB/s │
└────────────────────────────────────────────┘
```

- **点任意一行** = LidAwake 替你按下那个真实的菜单栏项，弹出的是**那个 App 自己原汁原味的菜单**。
  我们不解析、不代理、不重绘它的菜单
- `›` 表示该项支持程序化点击。少数 App 的项不提供 `AXPress`，会提示你先"展开菜单栏"再手动点
- **橙色「看不到」** = 这一项被系统裁掉了，屏幕上根本没有它
- 排序：**被裁掉的排最前面** —— 那才是你打开面板要找的东西
- 点面板外面或按 `ESC` 收起

## 四、能耗

| 时机 | 开销 |
|---|---|
| 面板关闭时 | **0** —— 不扫描、不采样、无定时器 |
| 面板打开时 | 1 秒一次系统状态采样（tolerance 0.2s）；AX 扫描只在打开瞬间做一次，在后台队列 |
| 功能未启用时 | 完全不创建那两个 status item，不注册快捷键 |

AX 是同步 IPC，遇到没响应的 App 会卡住，所以每个目标都设了 **0.25 秒**超时，
并且整个扫描在后台队列，绝不卡主线程。

全局快捷键用 Carbon 的 `RegisterEventHotKey` 而不是 `CGEventTap` ——
前者**不需要辅助功能权限**，不该为一个唤起面板的快捷键多要一个权限。

---

## 五、与守护进程的边界（重要）

**这个功能完全不碰 `lidawaked`。**

- 辅助功能 / 屏幕录制权限只在 **App 进程内**使用
- root 守护进程既不链接 ApplicationServices，也不链接 ScreenCaptureKit
- 纯逻辑（`MenuBarModel.swift`）放在 LidAwakeCore 里供单测，但**其中没有一行 AX 代码** ——
  Core 被守护进程链接，所以这条边界是硬性的
- 守护进程的 XPC 协议依然只能表达 `off` / `indefinite` / `until(秒数)`，没有因为这个功能扩大过

## 六、自检

```bash
/Applications/LidAwake.app/Contents/MacOS/LidAwake --selftest-menubar
```

会输出：权限状态 · 折叠状态切换验证 · 系统状态实测值 · （授权后）完整的菜单栏项列表，
标注哪些"看不到"、哪些可代点击。

## 七、默认值

| 项 | 默认 | 原因 |
|---|---|---|
| 菜单栏折叠功能 | **关闭** | 启用会往用户菜单栏加两个图标，这种改动必须显式同意 |
| 全局快捷键 ⌥⌘B | 开 | 零权限、零成本 |
| 真实图标预览 | **关闭** | 要屏幕录制，而且对隐藏项本来就无效 |
| 辅助功能 | 不主动索取 | 面板首次打开时用一张说明卡片引导，讲清换来什么 |
